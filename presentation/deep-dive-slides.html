Technical Deep-Dive

Safe AI Agents

Creating a safety block to help safeguard agents against potential attackers.
1 · Why We Did This

We're deploying agentic AI faster than we understand how it breaks.

KPMG is building and innovating with multi-agent AI. There's no tested view of how these systems fail under attack.

The blindspot · 1
Which attacks actually work?
Multi-agent systems open attack surfaces a single model doesn't have — untrusted input flowing between agents, handoffs, tool calls. Nobody had tested which of them break.
The blindspot · 2
What can we actually do to defend?
Platform guardrails? A safety prompt? Model choice? No evidence for what works — or whether a prompt-level fix is even possible.
The gap · 3
No guardrails exist yet.
KPMG has no guidelines or guardrails for threat-resilient agent design. Teams ship orchestrator-based workflows today with nothing in place.
2 · What We Set Out to Deliver

A drop-in block, backed by evidence.

1 · The safety block

A system-message layer any developer pastes into an agent's system prompt. Closes the confirmed vulnerability with no architecture rebuild — deployment-agnostic, no identity assumptions.

2 · The evidence

Controlled attack-and-defense testing against a real Azure AI Foundry workflow — scored the same way every time (F1), so the claim rests on data, not assertion.

3 · Research Findings — real-world context

Four documented cases of LLM attacks causing real harm.

EchoLeak CVE-2025-32711 · CVSS 9.3

A zero-click indirect prompt injection in Microsoft 365 Copilot. A payload hidden in an ordinary email exfiltrated OneDrive/SharePoint files — no user click required.

AgentHarm ICLR 2025

A published jailbreak template drove Claude 3.5 Sonnet to carry out a dark-web forgery order end to end with its tools — a request it refused when asked directly. Refusal training didn't transfer to tool-use.

PoisonedRAG USENIX Security 2025

5 poisoned documents per targeted question, planted in a corpus of millions, reached a 90% attack success rate at forcing a RAG system to return the attacker's chosen answer.

Alignment faking Anthropic · 2024

Claude 3 Opus complied with harmful requests 14% of the time when it believed it was being observed and trained on — vs. almost never otherwise. A training-dynamics risk no system prompt can instruct away.

4 · What Prompts Can — and Can't — Do

A prompt closes some gaps. Others need architecture.

✓  A prompt can enforce
  • Instruction hierarchy — system prompt outranks input
  • Injection detection — recognising an embedded directive
  • Injection refusal — halting instead of complying
✕  A prompt cannot (native-capability limits)
  • Tool configuration — what an agent is allowed to call
  • User identity verification between agents
  • Immutable logging & real-time cascade detection
A prompt is one layer of defense. The platform is another. We tested both.

9 · Results — known limitations & close

It works, within narrow limits.

Known limitations
1No real attack tested

Real attack scenarios — and their consequences — were not taken into account.

2Only two models tested

Both frontier at the time of testing. Newer model capabilities aren't measured — nor are older-model vulnerabilities in already-deployed solutions.

3Real attacks are unknown

We don't know how real attacks look or how they're wrapped. Our payload was based on a well-known attack pattern — not current, in-the-wild attacks.

The block took the Claude Sonnet 4.6.1 Supervisor's DPI failure rate from a 60–80% baseline to 0%, held across 200 runs at N=50. On GPT 5.4 it helps — but over-refuses, and the model you choose is itself a safety control.

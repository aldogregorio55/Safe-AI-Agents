## Source-of-truth chain

```
Run capture files (test-runs/round-N/...)
            │
            ▼
f1-run-inventory.md          ← human-curated; definitive Pass/Fail + Classification
            │
            ├──────────────────────────┐
            ▼                          ▼
calculate_scores.py            build_live_workbook.py
            │                          │
            ▼                          ▼
f1-scoring-results.md          f1-scoring.xlsx
(text report)                  (working spreadsheet)
```

Both downstream artefacts must agree on counts. They differ only in display of one edge case (see "N/A vs 0.000" below).

## The two scoring tools

| Tool | When it's authoritative | When to use the other |
|---|---|---|
| [calculate_scores.py](../round-3/scoring/calculate_scores.py) | Always — this is the canonical computation. Verification, reports, citations. | Never override its counts. |
| [f1-scoring.xlsx](../round-3/scoring/f1-scoring.xlsx) | Team copy-paste, working session, what-if exploration | Don't cite raw cell values in writeups without confirming against the script. |

If the workbook and script disagree on a count, the workbook is wrong — re-check that [f1-run-inventory.md](../round-3/scoring/f1-run-inventory.md) and [build_live_workbook.py](../round-3/scoring/build_live_workbook.py)'s `RUN_METADATA` match, then rebuild.

## How to regenerate the live workbook

From the project root with the venv activated:

```powershell
python evidence\round-3\scoring\build_live_workbook.py
```

Output: `evidence\round-3\scoring\f1-scoring.xlsx` (overwrites prior version).

**Close the file in Excel before running** — Excel locks open files and the build will fail.

### Adding Phase B runs

1. Update [f1-run-inventory.md](../round-3/scoring/f1-run-inventory.md) with new rows.
2. Append matching `(run_id, model, mode, batch, result)` tuples to `RUN_METADATA` in [build_live_workbook.py](../round-3/scoring/build_live_workbook.py).
3. If a new (Model, Mode) combination appears, also add it to `PER_CELL_ROWS` and/or `PER_MODEL_ROWS`.
4. Append matching `Run(...)` entries to the `RUNS` list in [calculate_scores.py](../round-3/scoring/calculate_scores.py).
5. Run both:
   ```powershell
   python evidence\round-3\scoring\build_live_workbook.py
   python evidence\round-3\scoring\calculate_scores.py
   ```
6. Verify the two reports agree on counts.

All formula ranges in the workbook auto-adjust to the new run count via `RUNS_LAST_DATA_ROW = RUNS_HEADER_ROW + len(RUN_METADATA)`. No manual range fixes.

## N/A vs 0.000 — known display divergence

When a cell has **TP=0 and FP=0**, Precision is mathematically undefined (0/0). The Excel workbook and Python script disagree on how to display this:

| Tool | Precision | Recall | F1 | Rating |
|---|---|---|---|---|
| [f1-scoring.xlsx](../round-3/scoring/f1-scoring.xlsx) (via `IFERROR(...,"N/A")`) | `N/A` | `0.000` | `N/A` | `N/A` |
| [calculate_scores.py](../round-3/scoring/calculate_scores.py) (via `f1_score()` floor) | `N/A` | `0.000` | `0.000` | `Failing` |

**Both are defensible.** The script's `0.000 / Failing` tells the "zero defense" story directly. The workbook's `N/A` preserves mathematical purity (you can't compute a harmonic mean from an undefined input).

**Which to cite:** Use the script's `0.000 / Failing` for the writeup — it communicates the finding. Use the workbook for team-facing exploration. If you need to reconcile, note both values.

This divergence only matters for cells with zero detections. As soon as Phase B produces any TP, both tools converge on the same numbers.
